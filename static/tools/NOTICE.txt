The Python packages in vendor.zip are unmodified upstream source files.
engine.py is ES Doc's adapter for bounded reads, safe archive indexing,
path validation, split segments, streamed ZIP output and browser progress.
These tools do not execute game scripts or inject files into a game.
ZIP exports include original archive contents and recovered source scripts.
recovery.py adds static script-container recovery, inert compatibility records,
encoding-layer recovery and constant-byte XOR recognition for RPYC signatures.
The advanced archive adapter supports the xehsoidx header and extended
4/5/6/7-field index records based on the corresponding archive loader.
Container format reference: a locally inspected decoder and script-loading
library provided by the user. No game content is bundled.
Bytecode-only Python blocks are marked as partial recovery. Game loaders are
not rewritten or executed. Original containers remain alongside readable
sections for inspection/adaptation. Unknown custom encryption is not auto-supported.

Original licenses, copyright notices and metadata are included in each wheel's
dist-info directory inside bytecode.zip. Wheel URLs and SHA-256 digests are
recorded in manifest.json. Rebuild with prepare_tools.py --bytecode-only.
pyc_decompiler.py reads foreign marshal data without running module code.
Supported bytecode versions: Python 2.0 through 3.8, subject to upstream support.
Original PYC files are kept in ZIP exports even when recovery fails.
