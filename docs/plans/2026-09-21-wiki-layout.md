# Центрированный layout документации

**Цель:** убрать перекос влево и сделать поиск статьи, чтение и переход между разделами очевидными.

**Архитектура:** FastAPI/Jinja остаются источником страниц. Общие CSS-переменные задают центрированную оболочку; CSS Grid разделяет дерево статей, материал и локальное оглавление. Нативные details обеспечивают сворачивание без зависимости от JavaScript.

**Стек:** Jinja, CSS Grid, vanilla JavaScript; существующие цвета, шрифты и контент.

## Исследование и выбор

- [Wikipedia — пример статьи](https://en.wikipedia.org/wiki/Early_Netherlandish_painting): оглавление отдельно от материала, поиск в шапке, управление шириной.
- [MediaWiki — ограничение ширины](https://www.mediawiki.org/wiki/Reading/Web/Desktop_Improvements/Features/Limiting_content_width): вложенные ограничения для статьи и общего рабочего пространства. Длина строк и ширина технических материалов требуют разных решений.
- [The Last of Us Wiki](https://thelastofus.fandom.com/ru/wiki/The_Last_of_Us_Wiki): общий контейнер сообщества, страницы и локальной навигации. Рекламные и платформенные панели не нужны ES Doc.
- Context7 `/mdn/content`: CSS Grid с гибкой средней колонкой, min-width: 0; нативные details/summary и адаптивное раскрытие.
- [WAI Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/): понятные управляющие элементы и клавиатурное раскрытие.

Рассмотрены простое центрирование, полноэкранная статья и три колонки. Выбраны три колонки: дерево 224px, гибкая статья, оглавление 224px внутри оболочки до 1536px. Полноэкранная ширина доступна по явному выбору читателя. Текст сохраняет левое выравнивание.

## Реализация

1. `static/css/vars.css`, `components.css`: общие ширины и поля; центрирование шапки, страниц, footer; компактные заголовки каталогов.
2. `templates/doc.html`, `static/css/doc.css`, `static/js/docs.js`: независимые навигации, текущая статья, breadcrumbs, настройка ширины, responsive disclosures, scroll-spy.
3. `templates/docs_index.html`, `templates/home.html`, `static/css/home.css`: двухколоночные тематические группы и полезные маршруты на широком экране; один порядок на мобильном.
4. `resources.css`, `artists.css`, `news.css`: согласование ширины списков и полос навигации; новости остаются ограниченной колонкой для чтения.
5. `header.html`, `search.js`, `components.css`: поиск доступен и без JS, мобильная кнопка появляется после инициализации.
6. Обновить `DESIGN.md` по фактически реализованному layout, убрав старые конфликтующие правила.

## Проверка

- Существующие Python-тесты, компиляция Jinja, синтаксис JS, `git diff --check`.
- Browser: 1920/1440/1024/768/390/320px, светлая и тёмная темы, длинные названия, длинная статья с кодом, каталоги и ресурсы.
- Проверить дерево, anchors и scroll-spy, клавиатуру и поиск, переносы, возврат с мобильного breakpoint, сохранение ширины, отсутствие горизонтального скролла страницы.
- Два ограниченных визуальных прохода: выявление проблем, пакетное исправление, подтверждение.
